# FaceAccess 设计说明

这份文档记录项目的技术选型理由、关键实现细节，以及开发过程中踩过的坑。
上手指南（怎么编、怎么跑）看根目录的 [README](../README.md)。

## 一、技术选型

| 环节 | 选择 | 理由 |
|---|---|---|
| 人脸检测 | YuNet（`FaceDetectorYN`） | 轻量，onnx 模型只有 345 KB，CPU 上能实时跑 |
| 特征提取与比对 | SFace（`FaceRecognizerSF`） | 输出 128 维特征，直接给余弦相似度接口 |
| 数据库 | SQLite（Qt `sql` 模块） | 免安装、单文件，适合这种单机小数据量场景 |
| 通信 | 串口（Windows API，非 `QSerialPort`） | Qt 未安装 SerialPort 模块，改用 `CreateFile` / `WriteFile` 后零额外依赖 |
| 视频输入 | 虚拟摄像头 | 开发机没有摄像头，用手机端虚拟摄像头软件把手机变成本机摄像头 |
| 执行器 | 舵机 SG90 | 有真实机械动作，直接当锁舌用，5V 供电 |
| 远程上报 | STM32 → MQTT → 网页看板 | 复用 STM32 实训固件里现成的 WiFi / MQTT 通道，不动主链路 |

上位机负责识别和记录，STM32 负责动作，串口做两者之间的桥，MQTT 单独走一条远程通道。

## 二、关键实现

### 2.1 人脸识别链路

```
摄像头帧 ──resize到640×480──► YuNet 检测 ──► 人脸框 + 5 个地标
                                                │
                                      按地标 alignCrop
                                                ▼
                                        112×112 规范脸
                                                │
                                          SFace 提特征
                                                ▼
                                        128 维 float 向量
                                                │
                            与库内人员特征逐个算余弦相似度
                                                ▼
                                  最高分 ≥ 0.363 → 判定身份
```

- **检测前必须统一尺寸**：YuNet 要求固定输入，代码里统一 `resize` 到 640×480，检测和提特征走的都是这个尺寸的帧。
- **阈值 0.363** 是 SFace 官方推荐值。实际用下来，误识别多就把阈值调高，认不出就把阈值调低。
- **模型加载约 1 秒**，所以 `FaceEngine` 用单例，保证整个进程只加载一次。C++11 起静态局部对象的初始化是线程安全的，懒汉式直接 `static FaceEngine s;` 就行。

### 2.2 特征怎么进数据库

SQLite 不认识 `cv::Mat`，所以特征要序列化：

```
cv::Mat (1×128, CV_32F)  ←→  QByteArray (512 字节)
                              = 128 × sizeof(float)
```

存的时候直接 `QByteArray((const char*)feature.data, feature.total() * feature.elemSize())`。
读回来时**必须先校验长度是不是 512**，不匹配就直接返回空 `cv::Mat`——否则一条损坏的记录会让
后面的 `memcpy` 按错误的尺寸读写，直接越界。

### 2.3 取帧与界面刷新

用 `QTimer` 每 100ms 触发一次取帧，而不是 `while(1)`——主线程被占住界面就没法响应了，
定时器驱动是 Qt 里做"循环"的惯用做法。

两个显示上的坑：

- OpenCV 的 `cv::Mat` 是 **BGR** 顺序，转 `QImage` 要用 `Format_BGR888`，用 RGB888 会红蓝互换；
- OpenCV 的 `putText` 画不了中文，所以**画面上只写英文**（`OK` / `UNKNOWN`），中文姓名放在 Qt 的 label 里。

### 2.4 同一个人只记一条

`lastRecognizedName` 记住上一帧识别到的人。同一个人连续出现在多帧里只写一条记录，
人离开画面（识别不到）才重置。这是这类"一次进入记一次"场景的真实需求，
否则 10 帧/秒会瞬间写满记录表。

另外，人员特征列表在启动时一次性读进内存，识别过程不去查库——10 帧/秒的频率顶不住每次查库的开销。

### 2.5 串口协议

| 项 | 值 |
|---|---|
| 波特率 | 115200，8 位数据，无校验，1 位停止（8N1） |
| 上位机 → STM32 | `OPEN:姓名\r\n`（无姓名时发 `OPEN\r\n`） |
| STM32 → 上位机 | 本项目的开锁链路是单向的，不用回执 |

STM32 侧（`door.c`）用 **UART1 中断接收 + 128 字节环形缓冲**。115200 波特率下每字节间隔
约 87 µs，靠 `door_task` 轮询取字节会把数据丢掉，所以中断里只负责往环形缓冲塞，
任务每 20ms 轮询一次缓冲、攒到换行符才解析整条命令。

> 注意解析用的是 `strncmp(line, "OPEN", 4)`，**区分大小写**，只认大写；
> 另外 `OPENXXX` 这种也会被当成开锁命令，严格来说应该按分隔符切词。

### 2.6 舵机 PWM

SG90 是 50Hz 定位舵机，脉宽 0.5ms → 0°、1.5ms → 90°、2.5ms → 180°。

```
TIM3_CH4 (PB1)
  72MHz ──预分频 72-1──► 1MHz ──ARR 20000-1──► 周期 20ms = 50Hz
  CCR 直接就是脉宽微秒数：500 / 1500 / 2500
```

开锁动作：舵机转到 90° + 蜂鸣一声 + LED3 点亮，2 秒后转回 0° 并熄灭。
同时把命令里的姓名提取到 `door_last_name`，供 MQTT 上报使用。

### 2.7 FreeRTOS 任务划分

| 任务 | 栈（字） | 优先级 | 职责 |
|---|---|---|---|
| `sensor` | 256 | 2 | 采集温湿度、空气质量、光照、人体感应 |
| `display` | 256 | 2 | OLED 刷新 |
| `alarm` | 128 | 3 | 越限报警（蜂鸣 + LED0~2） |
| `mqtt` | 512 | 1 | 每 2 秒上报一次数据 |
| `key` | 128 | 2 | 按键扫描与页面切换 |
| `door` | 256 | 2 | 串口命令解析与开锁动作 |

内核用 heap_4，`configTOTAL_HEAP_SIZE` 配成 16KB。

### 2.8 MQTT 报文与看板

STM32 侧没上 MQTT 库，`mqtt.c` 自己拼报文（CONNECT / PUBLISH / SUBSCRIBE），
再通过 ESP8266 的 AT 指令走 WiFi 发出去。

| 项 | 值 |
|---|---|
| Broker | `broker.emqx.io:1883`（公共测试服务器） |
| 上报主题 | `smart_home/test`，每 2 秒一次 |
| 指令主题 | `smart_home/cmd`（远程布防 / 撤防） |
| 上报内容 | 温度、湿度、空气质量、光照、人体、报警状态、布防状态、开锁人姓名 |

看板 `dashboard.py` 是 Flask + paho-mqtt：后台线程订阅 `smart_home/test` 更新一份共享数据，
网页端用 HTTP 拉取并渲染，另有按钮向 `smart_home/cmd` 发布布防/撤防指令。

这条 MQTT 链路和开锁用的串口是**两条完全独立的通道**——一条走 USB 串口接收命令，
一条走 WiFi 上报状态，互不影响。

## 三、踩坑记录

### 3.1 引脚冲突：ADC 自检抢走了舵机 PWM 口

**现象**：开机自检时舵机能摆一下，之后发开锁命令完全不动。

**排查**：打印 CCR 寄存器发现值改对了（500 → 1500），说明定时器没问题；
再查引脚模式才发现 PB1 被配成了模拟输入。

**原因**：`adc_test.c` 里维护了一张 ADC 候选引脚表，`adc_test_init()` 会把表里
**所有**引脚统一设成模拟输入，把 PB1 的复用推挽模式覆盖掉了。又因为 `adc_test_init()`
排在舵机自检之后才执行，所以只有开机那一次能动。

**修复**：把 PB1 从 ADC 候选表里删掉，通道数从 10 改为 9。

同一张表里的 **PC1 也是 DHT11 的数据脚**，同样被抢过；但 `dht11.c` 每次读取前都会重新
`HAL_GPIO_Init` 把引脚切回来，等于自己抢回去了，所以一直没暴露。
教训是：**候选表里不要放任何已经占用的引脚**，哪怕当下看着"没事"。

### 3.2 FreeRTOS 堆不够，任务静默创建失败

加上第 6 个任务 `door_task` 之后，8KB 堆不够用，`xTaskCreate` 直接失败——
而且它**不报错**，只是任务根本不跑。

**修复**：`configTOTAL_HEAP_SIZE` 改成 16KB。
另外 `xTaskCreate` 的返回值当时没人检查，这是个隐患，值得补上判断。

### 3.3 报警任务把开锁提示灯灭掉

撤防之后 `alarm_task` 仍然每 200ms 把 LED0~2 关一次，开锁刚点亮的提示灯被当场灭掉。

**修复**：开锁提示改用 **LED3（PA14）**，和报警占用的 LED0~2（PA11~13）完全错开，
两个任务各管各的灯。比直接把整个报警任务注释掉干净，报警功能还能用。

### 3.4 UART 溢出后串口永久失效

**现象**：系统跑一会儿 UART1 突然什么都收不到，敲 `OPEN` 没反应。
而定时器、CCR、舵机连线全都是好的，很容易误判成舵机故障。

**原因**：`HAL_UART_Receive_IT` 会打开 PEIE / EIE；一旦出现溢出错误（ORE），
`HAL_UART_IRQHandler` 走 blocking error 分支，调 `UART_EndRxTransfer()` 关掉
RXNEIE / PEIE / EIE 并把 `RxState` 置为 READY，然后调用 `HAL_UART_ErrorCallback()`——
而工程里没人实现这个回调（用的是 HAL 的 `__weak` 空函数），于是接收既不重启、
也没有任何提示，串口就此静默。

**修复**：自己实现 `HAL_UART_ErrorCallback()`，判断到 `huart->Instance` 是 USART1（或 USART3）时，
`__HAL_UART_CLEAR_OREFLAG` 清标志并重新 `HAL_UART_Receive_IT`。

### 3.5 MQTT 剩余长度字段只编了一字节

`mqtt.c` 里写的是 `buf[i++] = (uint8_t)remaining;`。

MQTT 的"剩余长度"是**变长编码**，超过 127 必须用两字节表示。
后来上报内容里加了开锁人姓名字段，整包涨到 90~100 字节，离 127 不远，
姓名一长整包就错乱。

**修复**：改成按变长编码规则生成。

### 3.6 ESP8266 的 +IPD 被串口中断分片

远程布防/撤防偶尔失效，原因是 `wifi_extract_ipd` 只缓存了一个 `+IPD` 报文，
而 WiFi 模块返回的数据会被 UART3 中断切成好几段送达，
`strstr` 在单段里当然找不到完整的 `+IPD`。

**修复**：改成跨轮询累积缓冲（`mqtt_rx_acc[256]`），凑齐了再解析。

### 3.7 上位机读特征没校验长度

`bytesToFeature` 原本不检查 `QByteArray` 长度，库里只要有一条损坏记录就会按错误的
尺寸 `memcpy`。**修复**：加 `if (ba.size() != 512) return cv::Mat();`。

## 四、已知隐患

1. **报警默认开启且阈值偏低**：`g_alarm_enabled` 默认为 1，`AQI_ALARM_LV` 设成 `AQI_UNHEALTHY`。
   室内 MQ-135 读数一飘高就每 200ms 蜂鸣一次，会把开锁提示音盖掉。
   演示前建议默认撤防，或者把阈值抬一档。
2. **PIR 中断优先级配置不当**：`pir_cb` 的中断优先级是 2，低于 FreeRTOS 的
   `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`（5），不受 basepri 屏蔽。
   目前 `pir_cb` 没有注册所以没暴露，但在里面调 FreeRTOS API 会直接把内核搞崩。
   USART1 / USART3 用的 6 是对的。
3. **`led_all_init()` 关掉了 SWD**：为了把 PA13 / PA14 当普通 LED 用，
   函数里调了 `__HAL_AFIO_REMAP_SWJ_DISABLE()`。程序一跑起来调试器就连不上，
   要用 connect under reset 才能重新烧录。
4. **`xTaskCreate` 返回值没人检查**：堆不够时是静默失败的（见 3.2）。
